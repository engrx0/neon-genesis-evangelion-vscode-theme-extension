# Project direction

The current repository and manifest version is `0.3.0`. A focused `v0.3.1` quality release is the proposed next release, not a current publishing commitment.

## Quality-release candidate

- Rebalance contrast and semantic hierarchy across the three existing themes.
- Test representative C++, TypeScript, Python, Dart, JSON, and Markdown files.
- Replace the icon, hero image, and screenshots with original assets and sanitized paths.
- Rewrite the README and Marketplace copy with a concise unofficial-fan-project disclaimer.
- Add theme and manifest validation plus a packaging smoke test.
- Trim unnecessary files from the extension package and update the changelog.
- Revoke any previously exposed publishing credential and create a minimally scoped replacement only when a release is approved.
- Publish only after a release review confirms readability, package hygiene, privacy, rights, and credential safety.

## Later theme possibilities

Do not delay the quality release for a fourth theme.

- **NERV Terminal**: charcoal and black surfaces, restrained amber and warning red, cyan system-state accents, and a utilitarian command-center feel.
- **SEELE Monolith**: near-black, bone white, and muted red; minimal and severe.
- **Mass Production**: white and grey surfaces with blood-red and black accents.

## Content possibilities

- Clean screenshots covering each theme and shared UI states.
- Short videos about before-and-after changes, readability decisions, and packaging or release work.
- A build log distilled into a case study.
- A launch post followed by technical and visual follow-ups.

## Decisions required before release work

- Whether `v0.3.1` remains the next release target.
- Which replacement visual assets are original and safe to publish.
- Which contrast targets and representative languages define acceptance.
- Whether the later theme candidates remain part of the roadmap.
